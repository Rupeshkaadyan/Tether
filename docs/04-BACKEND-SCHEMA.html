Encryption boundary

Columns marked BYTEA hold AES-256-GCM ciphertext produced on device. The server has no key and cannot read them. Never add a plaintext column for journal or AI content — not even for debugging.

user_tracks

This table is the moat

Track selection is per user, not per couple. An interfaith couple has two different rows here. Shared prompts are generated from the intersection of both.

CREATE TABLE user_tracks (
  user_id       UUID         NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  track_id      wisdom_track NOT NULL REFERENCES wisdom_tracks(id),
  is_primary    BOOLEAN      NOT NULL DEFAULT true,
  selected_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, track_id)
);

ai_memory_embeddings

Couple memory — the defensible feature

Enables the coach to reference what happened weeks ago. Retrieval must be scoped to user_id = requester OR visibility = 'shared'. Never retrieve a partner's private entries.

CREATE TABLE ai_memory_embeddings (
  id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID        NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  couple_id   UUID        REFERENCES couples(id) ON DELETE CASCADE,
  source_type entry_source NOT NULL,
  source_id   UUID        NOT NULL,
  embedding   VECTOR(1536) NOT NULL,
  visibility  visibility  NOT NULL DEFAULT 'shared',
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX memory_user_idx ON ai_memory_embeddings (user_id);
CREATE INDEX memory_couple_idx ON ai_memory_embeddings (couple_id);
CREATE INDEX memory_vec_idx
  ON ai_memory_embeddings USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

safety_events

No content, ever

This table stores no user text. Category and action only. This is intentional: a safety log must never become a readable archive of someone's worst moment.

  source       entry_source NOT NULL,
  source_id    UUID,

10Row Level Security policies

Release gate

RLS must be enabled on every table, and policies must be verified by automated tests in CI. A policy gap here is the single worst possible bug in this product.

ALTER TABLE profiles                ENABLE ROW LEVEL SECURITY;

-- Helper: is this user an active member of this couple?
CREATE OR REPLACE FUNCTION is_member_of(cid UUID)
RETURNS BOOLEAN LANGUAGE sql STABLE AS $$
  SELECT EXISTS (
    SELECT 1 FROM couple_members
    WHERE couple_id = cid AND user_id = auth.uid() AND is_active
  );
$$;

-- Own rows
CREATE POLICY own_profiles ON profiles
  FOR ALL USING (id = auth.uid());

CREATE POLICY own_tracks ON user_tracks
  FOR ALL USING (user_id = auth.uid());

CREATE POLICY own_journal ON journal_entries
  FOR ALL USING (user_id = auth.uid());

CREATE POLICY own_mood ON mood_logs
  FOR ALL USING (user_id = auth.uid());

CREATE POLICY own_safety ON safety_events
  FOR ALL USING (user_id = auth.uid());

-- Couple-scoped rows: shared only, private stays private
CREATE POLICY couple_replies ON prompt_replies
  FOR ALL USING (
    user_id = auth.uid()
    OR (is_member_of(couple_id) AND visibility = 'shared')
  );

CREATE POLICY couple_journal_shared ON journal_entries
  FOR SELECT USING (
    is_member_of(couple_id) AND visibility = 'shared'
  );

CREATE POLICY couple_pulse ON relationship_pulse
  FOR SELECT USING (is_member_of(couple_id));

CREATE POLICY couple_streaks ON streaks
  FOR SELECT USING (is_member_of(couple_id));

CREATE POLICY own_conversations ON ai_conversations
  FOR ALL USING (user_id = auth.uid());

CREATE POLICY own_messages ON ai_messages
  FOR ALL USING (
    EXISTS (
      SELECT 1 FROM ai_conversations c
      WHERE c.id = conversation_id AND c.user_id = auth.uid()
    )
  );

-- Critical: never retrieve partner's private memory
CREATE POLICY scoped_memory ON ai_memory_embeddings
  FOR SELECT USING (
    user_id = auth.uid()
    OR (couple_id IS NOT NULL AND is_member_of(couple_id) AND visibility = 'shared')
  );

CREATE POLICY invites_own ON invites
  FOR ALL USING (
    inviter_id = auth.uid()
    OR invitee_email = (SELECT email FROM auth.users WHERE id = auth.uid())
  );

12Migrations and seed data

Principles

  • All migrations are forward-only, numbered, and reversible via companion down-files.
  • Never drop a column in the same release that stops writing it. Two-phase: stop writing, then drop.
  • Encrypted column changes require a client migration path — plan a re-encrypt job, not an in-place alter.

Seed requirements for local and staging

Critical seed scenario

Include a couple where partner A is on the Biblical track and partner B is on the Secular track. Every shared-prompt decision must be tested against this pair. If the intersection logic is wrong, it will show up here first.

Sample query — daily prompt for a couple with differing tracks

-- Prompts that appear in BOTH partners' tracks, not yet used by this couple
SELECT p.id, p.body, p.category
FROM prompts p
WHERE p.track_id IN (
    SELECT track_id FROM user_tracks
    WHERE user_id IN (
      SELECT user_id FROM couple_members
      WHERE couple_id = $1 AND is_active
    )
  )
  AND p.is_live = true
  AND p.id NOT IN (
    SELECT prompt_id FROM prompt_replies WHERE couple_id = $1
  )
GROUP BY p.id, p.body, p.category
HAVING COUNT(DISTINCT p.track_id) = 1
ORDER BY p.day_index
LIMIT 1;
